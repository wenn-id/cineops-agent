**Severity: High**

## Problem

`src/core.mjs:48-60` — `rootCause.finding`, `decision`, and all three `actions` are string literals. They are returned unchanged for any input, so the function named `investigateIncident` does not derive its conclusion from the incident it is given.

## Evidence

A completely unrelated incident (subtitle pod crash-looping, no transcode stage at all) returns the transcode verdict verbatim:

```
input : INC-999 "Subtitle service down", single failed stage 'subtitles',
        single signal 'Subtitle pod is crash-looping.'

output: rootCause.stage   -> "subtitles"    <-- adapts
        rootCause.finding -> "GPU worker pool saturation caused the transcode
                              queue to spike and encoder jobs to time out."
        decision          -> "Premiere is at risk. Pause non-premiere 4K jobs
                              and drain the priority queue before 20:32 UTC."
        actions[0]        -> "Pause non-premiere 4K HEVC jobs."
```

Because `rootCause.stage` is the only field that adapts, the output is actively self-contradictory: it names the subtitle stage and then explains a GPU saturation failure.

The only real computation in the function is one sort over a `score` field that is itself hand-authored in `src/scenarios.mjs`, so even the evidence ranking is a pre-decided ordering being replayed rather than a computed one.

## Why it matters

The README describes this as a "deterministic local investigator that ranks metrics and logs, identifies a root cause, and produces a recovery decision." Ranking is real. Identifying a root cause and producing a decision are not happening.

## Two options

1. **Rename to what it is.** `renderIncidentReplay` / `replayFixture`, and move `finding` / `decision` / `actions` into `src/scenarios.mjs` next to the rest of the fixture. ~20 minutes, removes the overclaim entirely.
2. **Make it real.** Derive the finding from the top-ranked signal's stage and `finding` text, and select actions from a per-stage playbook keyed on the failed stage. Still deterministic, still offline, but the output would actually be a function of the input.

Option 2 is the stronger demo; option 1 is the safer one if time is short. This is the one real judgement call in the repo.

state:	OPEN
author:	wenn-id (Alwan Juliawan)
labels:	bug

assignees:	
projects:	
milestone:	
issue-type:	
parent:	
sub-issues:	
sub-issues-completed:	
blocked-by:

number:	5
--
**Severity: Medium**

## Problem

`src/core.mjs:40` computes confidence as `sum(top 3 scores) / 300`, capped at `0.99`. The `300` is an unexplained constant that assumes exactly three signals scored 0–100. Nothing enforces either assumption.

## Evidence

| Input | Reported | Problem |
| --- | --- | --- |
| 1 signal, score 100 | `0.33` confidence | A strong single signal reads as weak |
| 3 signals, score 5 each | `0.05` confidence **and** `critical` severity | 5% confident and critical at once |

Severity is derived from `failedStage` while confidence is derived from scores, so the two can disagree completely.

## Suggested fix

Name the constant and normalize against the evidence actually present:

```js
const MAX_EVIDENCE_SCORE = 100;
const confidence = evidence.length
  ? Math.min(0.99, Number((total / (evidence.length * MAX_EVIDENCE_SCORE)).toFixed(2)))
  : 0;
```

Also: `index.html:74` ships `96% confidence` as static markup, so the fixture's answer flashes before any run. Leave it empty and let JS populate it.

**Severity: Low** — grouped polish checklist, each item independent.

## Context

Worth stating up front: the presentation layer verified well. No console errors, no horizontal overflow at 390×844, `prefers-reduced-motion` and `:focus-visible` both handled, a working skip link, and `aria-live` on the result regions. `--muted` on `--ink` measures ~6.5:1, passing WCAG AA. The items below are refinements, not defects.

## Checklist

- [ ] **Repo weight.** `docs/` holds ~1.8 MB of PNGs in a repo whose entire source is ~28 KB. Compress them, or move demo media out of the repo.
- [ ] **Label type size.** Several labels run at 8–9px (`.eyebrow`, `.stage p`, `.hero-copy dt`). Contrast passes, but the size is below comfortable reading. Consider a 10–11px floor.
- [ ] **Dead link.** `<a class="brand" href="#">` is a link that goes nowhere. Make it a non-interactive element, or point it at `/`.
- [ ] **Redundant tooltip.** `<code title="...">` duplicates its own text content into the `title` attribute, which some screen readers announce twice.
- [ ] **No `package-lock.json`.** Acceptable only while the dependency count is genuinely zero; commit one as soon as a dependency is added.
- [ ] **Optional hardening.** No CSP meta tag. Cheap to add for a static page and demonstrates security awareness.
